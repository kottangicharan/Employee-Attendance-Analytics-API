# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Created without `tz_aware=True`, so PyMongo returns naive datetimes. Subtracting them from aware ones raises, and `.date()` on them is the UTC date. | `punch_out - punch_in` → `TypeError: can't subtract offset-naive and offset-aware datetimes` → 500. | `tz_aware=True`. Every datetime is now aware UTC, and IST is used only to get a date or a clock time. |
| 2 | startup | No indexes created. The only uniqueness guard is check-then-insert, and every list/analytics query is a COLLSCAN. | Explain on `/attendance` shows COLLSCAN. Two parallel duplicate creates both return 201. | `lifespan` creates the unique `emp_code` index, the unique `(emp_code, date)` index and the query indexes (see DECISIONS.md). `create_index` is idempotent. |
| 3 | `ms_to_dt` / punch-in `datetime.fromtimestamp(ms / 1000)` | Naive local-time datetime (whatever TZ the server has), and fractional seconds are kept, but R1 says truncate. | Server in UTC vs IST gives different `date`. `…900` ms is stored as `.9` s and returned as `…900`. | `datetime.fromtimestamp(ms // 1000, tz=timezone.utc)`. |
| 4 | `PunchInIn.punched_at: Optional[int]` | Accepts seconds-looking values, and pydantic's lax mode also accepts `"1783312500000"` strings and `1.7e12` floats. | `punched_at: 1783312500` stores a 1970 date instead of returning 422. | `StrictInt` with `ge=100_000_000_000, le=4_102_444_800_000`. |
| 5 | `PunchInIn.status: str` | Any string is accepted, including `ABSENT`, `LEAVE` or `"foo"`. | `{"status": "LEAVE"}` creates a LEAVE record that has a punch-in. | `Literal["PRESENT", "WFH", "ON_DUTY"]` → 422. |
| 6 | `punch_in` | `emp` is not checked for `None`. | Unknown `emp_code` → `TypeError: 'NoneType' is not subscriptable` → 500. | 404 `employee not found`. |
| 7 | `punch_in` `if body.punched_at` | Truthiness test. `0` would be treated as "now". | Edge case only, now also blocked by #4. | `is not None`. |
| 8 | `punch_in` `d = ts.date()` | Uses the date of a naive/UTC datetime, not the IST date, and ignores overnight shifts (R1). | Punch at 02:00 IST (20:30 UTC the previous day) gets the wrong date. A 05:00 punch on a 22:00–06:00 shift should belong to the previous day. | `attendance_date()` converts to IST and moves overnight early-morning punches to the previous day. |
| 9 | `punch_in` find-then-insert | Race: two parallel requests both pass `find_one` and both insert. | 8 parallel identical punch-ins → several 201s and duplicate records. | Unique `(emp_code, date)` index. `insert_one` catches `DuplicateKeyError` → 409. |
| 10 | `punch_in` response | Returns `id` (internal `_id`) and raw datetimes, not epoch ms. | Response has `"id": "66…"` and ISO strings for `punch_in`. | `record_out()` shapes every record: no id, instants as epoch ms, missing legacy fields defaulted. |
| 11 | `compute_late_minutes` | `punch_in.replace(hour, minute)` uses the punch's own tz/date, not IST shift start on the attendance date. The grace test is on whole minutes (`minutes > 10`), not "strictly more than 10:00". | Shift 09:30: 09:40:30 → 0 (should be 10), 09:40:59 → 0. Overnight punch after midnight gets a negative value. | Build shift start as `datetime.combine(att_date, shift_start, IST)`, test `secs > 600`, return `secs // 60`. |
| 12 | `compute_work_hours` | `round(float, 2)` is banker's rounding on a binary float, not half-up (R4). | 18 s → 0.005 h → `round` gives 0.0, should be 0.01. | `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`. |
| 13 | `compute_overtime` | No 30-minute minimum (R3). For overnight shifts the end is on the start date, not the next day. Also uses truncation instead of floor. | 18:35 punch-out → 5 min overtime (should be 0). Overnight 06:40 out → huge negative, clipped to 0 (should be 40). | `+1 day` when `shift_end <= shift_start`, floor minutes, `>= 30` else 0. |
| 14 | `create_employee` | Check-then-insert race, so concurrent duplicates both get 201. `created_at = datetime.now()` is naive local time and is returned as a datetime, not ms. | Parallel duplicate POSTs. Response `created_at` is an ISO string. | Rely on the unique index (`DuplicateKeyError` → 409). Store aware UTC, return epoch ms. |
| 15 | `EmployeeIn` | No validation: any `emp_code`, email, shift text, `joined_on`. `shift_start == shift_end` is allowed. | `joined_on: "2026-02-30"` or `shift_start: "25:00"` is stored. | Field patterns/lengths from the contract, real-date check, model validator for equal shifts. |
| 16 | `list_employees` | `skip = page * page_size` skips the first page. `total` ignores the department filter. No sort. No bounds on `page`/`page_size`. | `?page=1` returns items 21–40. `?department=X` total = whole collection. `page=0` / `page_size=10000` accepted. | `(page-1)*page_size`, `count_documents(q)`, sort by `emp_code`, `page ≥ 1`, `1 ≤ page_size ≤ 100`. |
| 17 | `list_employees` | Returns raw `created_at` datetime. | — | `employee_out()` returns epoch ms. |
| 18 | `list_attendance` | Loads the whole filtered collection into Python, sorts and slices it there. Sort is only `date` desc (no `emp_code` tiebreak). | Slow and memory-heavy at 100k docs. Order inside a date is random. | DB-side `find().sort([date -1, emp_code 1]).skip().limit()`, backed by the `(date -1, emp_code 1)` index. `count_documents` for total. |
| 19 | `list_attendance` params | No validation of dates, `status`, `page`, `page_size`. `date_from > date_to` is accepted. | `?status=foo` → empty 200. `?page=0` → strange slice. | `Status` literal, date pattern + real-date check, `date_from > date_to` → 422, R10 bounds. |
| 20 | `list_attendance` output | Returns `id` and raw datetimes. Legacy docs without `half_day`/`history` are returned without those fields. | Sample doc #9 comes back missing `half_day` and `history`. | `record_out()` defaults `half_day=false`, `history=[]`, `late_minutes`/`overtime_minutes=0`. |

**Looked at and judged fine:**
- `dt_to_ms` using `(dt - EPOCH) // ONE_MS` is exact integer arithmetic (no float `timestamp()` error), so I kept it.
- `/health` pings MongoDB and maps `PyMongoError` to 503. That is correct.
- `load_dotenv()` defaults to `override=False`, so real environment variables already win over `.env`.
- Sync (`def`) endpoints with PyMongo are fine: FastAPI runs them in a thread pool, and correctness under concurrency comes from the database (unique index, conditional updates), not from the Python process.
